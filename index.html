SDK Integration & Customization via Callback

Pendekatan integrasi manual yang memberi tim developer fleksibilitas lebih tinggi: memanfaatkan callback mechanism IronSKY SDK untuk menangani security event secara langsung di sisi aplikasi, secara real-time.

Metode: SDK callback Latensi: real-time Target: tim developer

Ringkasan

Di luar integrasi berbasis log forwarding, SecIron menyediakan SDK Integration secara manual yang memberikan fleksibilitas lebih tinggi bagi tim pengembang aplikasi. Melalui pendekatan ini, developer dapat memanfaatkan callback mechanism yang disediakan oleh IronSKY SDK untuk menangani security event secara langsung di sisi aplikasi, tanpa menunggu proses export/pull.

Dengan menerima event pada saat terjadinya, aplikasi dapat meneruskan event tersebut ke sistem eksternal, khususnya SIEM, secara real-time untuk kebutuhan monitoring dan korelasi insiden.

Callback Mechanism

Aplikasi mendaftarkan sebuah callback untuk tipe RISKEVENT. Setiap kali IronSKY mendeteksi ancaman, callback dipanggil beserta detail event dalam bentuk JSON. Urutan pemanggilan berikut wajib diikuti:

urutan inisialisasi (Android)
1. registerService(callback, Type.RISKEVENT, 0.5)   // daftarkan callback lebih dulu
2. registerService(callback, Type.DEVINFO, 0.5)      // sidik jari perangkat (udid)
3. setUserId(context, userId)                        // kaitkan user id
4. initAppsecEverisk(context, LICENSE_KEY)           // inisialisasi paling akhir
PentingPemanggilan registerService harus dilakukan sebelum initAppsecEverisk. Bila terbalik, callback tidak akan terpanggil.

Struktur Event

Objek yang diterima callback RISKEVENT berisi antara lain:

contoh payload callback
{
  "key": "event_risk_root",           // jenis event keamanan
  "name": "Root Detected",
  "riskLevel": "high",                 // low | medium | high
  "responseType": 1,                   // aksi RASP
  "responseI18n": "[{...pesan terlokalisasi...}]",
  "eventId": "1141###<udid>###...###event_risk_root",
  "time": 1789828899241
}
FieldKeterangan
keyJenis event keamanan (root, injection, MITM, dan lainnya).
nameNama singkat event.
riskLevelTingkat risiko: low, medium, atau high.
responseTypeKode aksi respons yang direkomendasikan SDK.
responseI18nPesan respons terlokalisasi (judul, isi, tombol).
eventId / timeIdentitas unik event dan waktu kejadian.

Use Case: Server Forwarder (Realtime ke SIEM)

Aplikasi meneruskan setiap event callback ke sebuah server forwarder milik klien, yang menormalkan lalu merelay-nya ke SIEM secara real-time. Forwarder dibangun dan dijalankan di sisi klien.

alur
   Mobile App + IronSKY SDK          Server Forwarder (klien)          SIEM
        callback RISKEVENT  ── POST ─▶  terima + normalisasi  ────▶  rules → alert

1. Sisi Aplikasi

Di dalam callback, bangun payload lalu kirim via HTTP POST ke endpoint forwarder. Jalankan di thread background agar tidak memblokir UI. Nilai deviceUdid diperoleh dari callback DEVINFO (lihat urutan inisialisasi).

Kotlin — teruskan event dari callback
val payload = JSONObject().put("ironsky", JSONObject()
    .put("security_event", ev.optString("key"))
    .put("risk_level", ev.optString("riskLevel"))
    .put("udid", deviceUdid)
    .put("event_time", ev.optLong("time")))

Thread {
    val c = URL("https://forwarder.internal/ironsky").openConnection() as HttpURLConnection
    c.requestMethod = "POST"; c.doOutput = true
    c.setRequestProperty("Content-Type", "application/json")
    c.setRequestProperty("Authorization", "Bearer <TOKEN>")
    c.outputStream.use { it.write(payload.toString().toByteArray()) }
    c.inputStream.close()
}.start()

2. Server Forwarder (implementasi referensi)

Forwarder menerima event, memverifikasi token, lalu menuliskannya ke lokasi yang dibaca SIEM. Contoh minimal dengan Python:

forwarder.py
from flask import Flask, request, abort
import json

app = Flask(__name__)
OUT = "/opt/ironsky/out/events.jsonl"   # lokasi yang dibaca SIEM

@app.post("/ironsky")
def ingest():
    if request.headers.get("Authorization") != "Bearer <TOKEN>":
        abort(401)
    ev = request.get_json(force=True, silent=True) or {}
    with open(OUT, "a") as f:
        f.write(json.dumps(ev, ensure_ascii=False) + "\n")
    return ("", 204)

3. Sisi SIEM

SIEM membaca output forwarder sebagai log JSON, sama seperti pada metode S3, sehingga rule yang sama berlaku. Contoh Wazuh:

/var/ossec/etc/ossec.conf
<localfile>
  <log_format>json</log_format>
  <location>/opt/ironsky/out/events.jsonl</location>
</localfile>
CatatanSamakan skema payload dengan metode S3 (bungkus di bawah ironsky, mis. ironsky.security_event) agar rule/korelasi SIEM dapat dipakai untuk kedua metode. Jalankan forwarder di belakang HTTPS dan gunakan token autentikasi.

Catatan Implementasi

  • Jalankan pengiriman jaringan di thread background agar tidak memblokir UI.
  • Nilai key pada callback identik dengan field Security event pada metode S3, sehingga aturan korelasi di SIEM dapat dipakai untuk kedua metode.
  • Penerusan ke SIEM lewat server forwarder dijelaskan pada bagian Use Case: Server Forwarder di atas.
